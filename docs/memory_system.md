# 🧠 Система автономной памяти Джарвиса

## Обзор

Система памяти Джарвиса реализует механизм долгосрочного хранения информации с использованием векторной базы данных ChromaDB. Система обеспечивает:

1. **Автономное сохранение** важной информации из диалогов
2. **Иерархическую структуру** связанных фактов через механизм Distance
3. **Фильтрацию** по уровню важности
4. **Семантический поиск** релевантного контекста

## Архитектура

Система памяти состоит из следующих компонентов:

- **MemoryManager** (`core/memory_manager.py`) - основной класс для работы с ChromaDB
- **Tool Definition** (`core/llm_engine.py`) - определение инструмента для Gemini
- **Настройки** (`config/settings.py`) - конфигурация системы памяти
- **Инструменты** (`tools/`) - утилиты для работы с памятью

## Механизм Distance

Система автоматически устанавливает связи между похожими фактами:

1. При добавлении нового факта выполняется семантический поиск по существующим записям
2. Если найден похожий факт с distance < `MEMORY_THRESHOLD` (0.35), устанавливается связь parent_id
3. Это создает древовидную структуру связанных фактов

```
Факт A
  └── Факт B (parent_id = A)
      └── Факт C (parent_id = B)
```

## Фильтрация по важности

Каждый факт имеет уровень важности от 1 до 5:

- **1** - неважная информация (не сохраняется)
- **2** - низкая важность
- **3** - средняя важность
- **4** - высокая важность
- **5** - критически важная информация

Факты с важностью 1 автоматически отфильтровываются и не сохраняются в базу данных.

## Автономное сохранение

Модель Gemini 2.0 автоматически определяет, когда нужно сохранить информацию:

1. Модель анализирует диалог и выявляет важные факты
2. Самостоятельно оценивает важность (от 1 до 5)
3. Генерирует теги для категоризации
4. Вызывает функцию `save_to_memory` через механизм Function Calling

## Метаданные

Каждый факт хранится со следующими метаданными:

- **importance** - уровень важности (2-5)
- **tags** - массив тегов для категоризации
- **timestamp** - время сохранения
- **parent_id** - ID связанного факта (если есть)
- **другие поля** - опциональные метаданные

## Использование в коде

### Добавление факта

```python
from core.memory_manager import MemoryManager

memory = MemoryManager()

# Добавление факта с метаданными
fact_id = memory.add_fact(
    text="Босс любит кофе с молоком без сахара",
    metadata={
        "tags": ["предпочтения", "напитки"],
        "source": "диалог"
    },
    importance=4  # Высокая важность
)
```

### Получение релевантного контекста

```python
# Получение контекста по запросу
documents, distances = memory.get_relevant_context(
    query="Что любит пить босс?",
    n_results=3
)

# Вывод результатов с релевантностью
for fact, distance in zip(documents, distances):
    relevance = 1 - distance  # Преобразуем дистанцию в релевантность
    print(f"Факт: {fact} (релевантность: {relevance:.2%})")
```

## Настройка

Основные параметры системы памяти находятся в `config/settings.py`:

```python
class MemorySettings:
    DB_PATH = "data/vector_db"  # Путь к базе данных
    COLLECTION_NAME = "jarvis_memory"  # Название коллекции
    EMBEDDING_MODEL = "all-MiniLM-L6-v2"  # Модель эмбеддингов
    MEMORY_THRESHOLD = 0.35  # Порог дистанции для связывания фактов
```

## Технические детали

- **Модель эмбеддингов**: all-MiniLM-L6-v2 (384-мерные векторы)
- **Устройство**: MPS (оптимизировано для Apple Silicon)
- **Метрика близости**: косинусное расстояние
- **Порог связывания**: 0.35 (настраиваемый)

## Примеры использования

При последующем диалоге:

Джарвис извлекает релевантный контекст и отвечает на основе сохраненной информации.
